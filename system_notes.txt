WFA Procurement — System Notes

Overview
- Single‑page web app for operations: inventory, pallets, suppliers, SDS, and saved deduction forms.
- Frontend only (no server). Data stored in Firebase (Auth + Firestore). Deployed on Netlify.
- Router uses URL hash (e.g., #/home, #/inventory/cartons-and-lids).

Tech Stack
- Firebase SDK (modules via CDN) for Firestore + Email/Password Auth.
- Netlify for static hosting.
- Vanilla JS modules, no bundler required.
- CSS: single file with layout, components, tables, and modals.

Key Directories and Files
- index.html                HTML shell, sidebar + main layout.
- css/style.css             Styles for layout/components/tables/modals.
- js/firebase.js            Initializes Firebase app, Firestore, and Auth. Exports SDK helpers.
- js/main.js                App bootstrap: runs initApp() and wires hashchange → renderRoute().
- js/app.js                 Core app module: router, shared UI wiring, non‑Home features (inventory, sds, suppliers, pallets).
- js/config.js              Configuration arrays (inventory categories, SDS locations).
- js/core/dom.js            DOM helpers ($, $$).
- js/core/utils.js          esc/escapeHtml, slugify, fmtDate, downloadCsv.
- js/features/home.js       Home page “Saved Forms” tiles and modals (Create, Edit, Open/Post).

Routing (hash based)
- #/home            Home page with Saved Forms tiles and Create button.
- #/inventory/:cat  Inventory per category (stock levels, add/deduct/import/new item, reorder thresholds).
- #/pallets         Pallet unloading log with CSV export.
- #/sds             SDS chemicals registry with CRUD and CSV export.
- #/suppliers       Suppliers list with CRUD and certificate links.
- #/po              Purchase Orders: add + list + status (Pending, Received with Back Order, All Items Received) with filters.
- #/reports         Placeholder (Reports coming soon).
- #/settings        Placeholder (Settings coming soon).

High‑Level Architecture
- index.html provides the static shell: locked sidebar, sticky topbar, content area.
- js/main.js calls initApp() in js/app.js, then renderRoute() on hash changes.
- js/app.js holds the router and delegates features, including Home which now lives in js/features/home.js.
- All pages render into the main content container (#page) and update the page title (#pageTitle).

Home: Saved Forms (js/features/home.js)
- Tile grid lists up to 100 saved forms from Firestore collection `order_forms` (ordered by created_at desc).
- Buttons per tile: Open, Edit, Delete.
  - Open: Modal for entering deduction quantities; posts stock movements and updates product SOH.
  - Edit: Modal that lets you rename the form and re‑select products (same UX as Create).
  - Delete: Asks for confirmation then deletes the form (requires login).
- Create Form: Opens category‑based selector modal with search and select‑all. Stores `item_ids` as product document IDs.

Form Modal (Open/Post)
- Header shows form title; top sticky toolbar contains category ribbon and Post Deductions button.
- Sticky table header for CODE / DESCRIPTION / SOH / DEDUCT / RESULT.
- Posting requires an authenticated user (Auth Email/Password). Each deduction:
  - Validates quantity ≤ current SOH.
  - Updates `products/{id}`: `soh` ↓ and `total_out` ↑.
  - Inserts a record in `stock_movements` with qty_delta negative, note includes form title.

Inventory (in js/app.js)
- Category view lists products with SOH and reorder cues based on `min_stock` and `target_stock`.
- Actions:
  - Deduct Mode: inline numeric inputs + “Apply Deductions” (posts movements + updates SOH).
  - Add Stock modal: increments `soh` and `total_in`, writes stock_movements.
  - New Item modal: creates `products/{id}` with initial stock and optional thresholds.
  - Bulk Import modal: paste TAB‑separated CODE + DESCRIPTION with presets for common categories.

Suppliers (in js/app.js)
- List with search and CSV export. Supports CRUD when logged in.
- Certificates field is an array of `{ title, url }`; a modal previews the list.

SDS (in js/app.js)
- Chemicals registry with location dropdown, PDF URL, and search. Supports CRUD when logged in and CSV export.

Pallet Monitoring (in js/app.js)
- Simple log per container/date with pallets count and note. CSV export provided. Delete requires login.

Firebase
- Project: configured in js/firebase.js using CDN SDK v10.
- Firestore collections used:
  - products
  - stock_movements
  - pallet_unloads
  - sdsChemicals
  - suppliers
  - order_forms
- Auth: Email/Password. Mutating actions require `auth.currentUser` checks in UI.

Security Rules (baseline suggested)
- Public reads; writes require auth.
- Consider hardening:
  - Make `stock_movements` append‑only (allow create, deny update/delete).
  - Disallow `products` delete and restrict updates if needed.
  - Optional: enforce creator‑only updates/deletes on editable collections.
  - Optional: validate `sdsChemicals.pdf_url` format.

Security Rules (current, 2025-10-11)
- File: FIRESTORE_RULES.rules
- Summary of changes:
  - Added `purchase_orders` collection with read + write restricted to authenticated users only.
  - Kept public read on other collections; writes still require auth.
  - `stock_movements` remains append‑only (create only; no update/delete).

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isAuthed() { return request.auth != null; }

    match /products/{docId} { allow read: if true; allow write: if isAuthed(); }
    match /stock_movements/{docId} { allow read: if true; allow create: if isAuthed(); allow update, delete: if false; }
    match /pallet_unloads/{docId} { allow read: if true; allow write: if isAuthed(); }
    match /sdsChemicals/{docId} { allow read: if true; allow write: if isAuthed(); }
    match /suppliers/{docId} { allow read: if true; allow write: if isAuthed(); }
    match /order_forms/{docId} { allow read: if true; allow write: if isAuthed(); }
    match /purchase_orders/{docId} { allow read, write: if isAuthed(); }
    match /{document=**} { allow read, write: if false; }
  }
}

Data Flow: Stock Deduction via Forms
1) Create or Edit a form to include product IDs.
2) Open form; optionally filter by category; enter deduction quantities.
3) Post Deductions:
   - Validate per row (SOH, presence).
   - Update `products/{id}`: decrement `soh`, increment `total_out`.
   - Create `stock_movements` record with negative `qty_delta`.

Deployment Notes (Netlify)
- index.html loads js/main.js (module), so no bundling is needed.
- If using path routes (not hashes) later, add a Netlify redirect to index.html.
- You may add caching headers (via netlify.toml) for assets and disable caching for HTML.

Setup (local testing)
1) Open index.html via a static server (or Netlify). Modules require http(s) (avoid file:// in some browsers).
2) Ensure your Netlify domain is whitelisted under Firebase Auth “Authorized domains”.
3) Verify Firestore Security Rules align with your intended read/write access.

Conventions
- Use document IDs as product identifiers when possible; fall back to matching by `code` if needed.
- All mutating UI flows require `auth.currentUser` and fail with a user alert if missing.
- CSV exports generate client‑side and download via a Blob.

Troubleshooting
- If forms fail to open, check DevTools console for Firestore permission errors.
- If the ribbon or sticky headers stack oddly, confirm CSS variables for toolbar height and sticky offsets.
- For network issues on restricted networks, initializeFirestore uses long‑polling to improve connectivity.

Purchase Orders (js/app.js)
- Add new PO via modal (PO Number required; Supplier/Description optional). Initial status = pending.
- Table lists POs with columns: PO Number, Supplier, Description, Status selector, Created time.
- Status selector values:
  - Pending
  - Received with Back Order (stored as 'backorder') — requires entering a back order note
  - All Items Received (stored as 'received') — considered closed
- Filters ribbon: All | Pending | Pending + Backorder | Closed.
- Table shows Backorder Note column (only populated when status is backorder).
- Firestore collection: `purchase_orders` with fields: po_number, supplier, description, status, backorder_note, created_at/by, updated_at/by.

Status change UX
- Confirmation is shown on every status change via custom modal (no native browser prompts).
- When switching to “Received with Back Order”, a modal requests a back order note; the note is saved in `backorder_note`.
- Leaving backorder clears `backorder_note` to null.

UI Modals (global)
- All confirmations and text inputs now use in‑app modals (not window.confirm/prompt).
- Helpers: `modalConfirm({ title, message })`, `modalPrompt({ title, label, placeholder, required })` in js/core/dom.js.
